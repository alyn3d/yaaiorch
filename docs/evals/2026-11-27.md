# Eval results, 27 November 2026

51 runs on 7 cases, graded by hidden tests the agents never see, on YAAIORCH 0.6.6: browser checks, the review
options, greenfield and repo groups. Every run passed and none was a false pass. Four results:

- **Browser checks cost almost nothing.** On the two web cases they added about $0.01 and a few seconds a run. They
  also changed nothing: every run passed in round 1 with or without them, because the agents fix these CSS bugs from
  reading the code. They stay on by default.
- **The plan critic, diff critic and review lens cost 25–44% more and caught nothing here.** The two cases built to
  need a fix round (`api-patch-contract`, `lib-retry-lint`) now pass in round 1 in every run, so these options and
  session resume, which act from round 2 on, had nothing to do. They stay off by default.
- **Greenfield works:** `orch new` on an empty repo passed all 3 runs, each goal first time, $0.72 a run for two goals.
- **Repo groups:** 6 of 6 passed with the integration fix of 26 November, none falsely, $1.36 and 3.5 minutes a group
  goal. Groups now stand at 22 of 24; both false passes predate that fix.

## Setup

- **Tier:** `economy`, full loop (`--no-fast`; the runner passes it for a plain tier). Configs: `+novisual` (no
  browser checks), `+noresume` (fix rounds start cold), `+critic` (plan critic), `+diffcritic` (diff critic next to
  QA), `+review` (built-in reviewer, lens bugs).
- **Repeats:** 3 runs per case and config. **Limits:** `--max-rounds 4`, `--max-cost 3` (`6` for a whole group),
  `--usage-cap 5h=60`.
- **Environment:** Claude Code on Windows, Chrome for the browser checks, agents without the user's plugins and hooks.
- **Cost** is the CLI's reported `total_cost_usd` (on a subscription it measures usage, not money spent).
  All runs together: $26.87.

## Browser checks

`web-dashboard-bug` (three causes of sideways scroll on phones and an unreadable dark-mode header) and `web-pricing`,
graded in a browser.

| config | runs | hidden pass | false pass | avg rounds | avg cost | avg time |
|---|---|---|---|---|---|---|
| economy (browser checks) | 6 | 6/6 | 0 | 1.0 | $0.30 | 1.1 min |
| economy+novisual | 6 | 6/6 | 0 | 1.0 | $0.29 | 1.0 min |

The architect decides per plan whether QA gets a browser check: it asked for one in 5 of the 6 runs. In the sixth
(`web-dashboard-bug` #3) QA passed the change from reading the CSS, and the hidden tests passed too. To show what
browser checks are worth, a case needs a page that reads right in the code and breaks on screen.
